# S23 Optimizer v1.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native; the box forbids parallel subagents). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.1.0: tested actions, restore/dry-run/access safety, measured before/after panel, full CI gates, Pages landing, README homepage.

**Architecture:** New logic goes in `core/` as pure Kotlin (testable on the JVM with fakes); `platform/` adapts Android/Shizuku to small interfaces; `ui/` only renders state. CI is the only build/test runner.

**Tech Stack:** Kotlin 2.0.21, Compose BOM 2024.12.01, Room 2.6.1, WorkManager 2.10, Shizuku 13.1.5, JUnit 4, Robolectric 4.14.1, Compose ui-test, Kover 0.9.1, ktlint 1.5.0 CLI, detekt 1.23.8 CLI.

**Spec:** `docs/superpowers/specs/2026-10-22-v1.1.0-design.md`

## Global Constraints
- Never run Gradle/Android build/emulator locally; verification = GitHub Actions on `upgrade/v1.1.0`.
- versionName `1.1.0`, versionCode `3`; CHANGELOG heading `## [1.1.0] - 2026-10-22`.
- No Room schema change; `SnapshotCodec` stays version 1.
- No URLs/hostnames/tokens from the dev environment in the repo; commit identity unchanged; push only via the gated script.
- Unknown values stay `null`/"unavailable", never `0`.

## Review Focus
- Shizuku dies between review and apply → apply must fail before journaling, no mutation (test in Task 2).
- Restore defaults when a value was changed by hand → CONFLICT kept, nothing overwritten (existing test + Task 2 per-kind test).
- Phone charged between two samples → level rises → window dropped (Task 3 test).
- Only one sample on one side of the pivot → "not enough data", not 0 %/h (Task 3 test).
- Package names with shell metacharacters in dry-run text → builder rejects before preview (Task 1 test).
