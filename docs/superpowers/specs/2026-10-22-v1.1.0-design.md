# S23 Optimizer v1.1.0 — design

## Intent
v1.0.0 works and CI is green, but the project has no homepage, a thin README, two test files and a single
build workflow. v1.1.0 makes it a showcase: every claim provable by a test or an on-device measurement,
every tweak undoable in one tap, and a public landing page.

## Goals (acceptance checks)
1. **Tests.** Unit tests for every optimizer action (background app-op, standby bucket, allowlisted disable,
   animation scale) and for the Shizuku command builder, pure Kotlin with a mocked shell; a Robolectric UI
   smoke test; a coverage report (Kover) in CI.
2. **Safety.** Every applied tweak is journaled and reversible with one-tap **Restore defaults**; a dry-run
   preview lists the exact commands (read, apply, verify, undo) before anything runs; Shizuku not installed,
   not running, permission not yet granted, permission denied and unsupported mode each get a clear message
   and an action, and block every mutation. Tests for each path.
3. **Measured value.** An in-app before/after panel: battery drain in %/h and app cold-start time, both from
   on-device counters, split at the first applied tweak, exportable as CSV. README states what is and is not
   measured.
4. **CI gates.** ktlint + detekt, unit + Robolectric tests, `assembleRelease` with the signed APK artifact on a
   tag (existing signing secrets), gitleaks, Dependabot, CodeQL (java-kotlin). All on GitHub Actions.
5. **Pages.** Landing page with screenshots captured from the real debug build on an emulator in CI, feature
   list, safety notes, download link; repository homepage set to it; HTTP 200 verified.
6. **Docs.** README as a homepage (banner, badges, screenshots, Shizuku install steps, tweak table with effect
   and undo, architecture mermaid, FAQ); `CHANGELOG.md` `[1.1.0] - 2026-10-22`; versionName 1.1.0 /
   versionCode 3; `SKILLS_USED.md`; `TASKS.md` + `HANDOFF.md`.
7. Branch `upgrade/v1.1.0` pushed through the gated push script, CI green on its head.

## Non-goals
- No new kinds of tweak, no root, no force-stop, no network permission.
- No Room schema migration (storage-format changes need the owner's approval).
- No merge to main, no PR, no tag (the coordinator does those). The `agent-mode` branch and the
  `v2.0.0-alpha1` tag stay untouched.

## Anti-goals
- A number on the panel or the landing page that was not measured on a device.
- Screenshots with invented data.
- A "restore" that overwrites a value the user changed by hand (existing conflict rule stays).

## Decisions (builder's calls)
- Drain rate uses consecutive snapshot pairs that are both `Discharging`, 5 min–12 h apart, with no level rise;
  pairs that straddle the first applied tweak are dropped. Fewer than 1 h of valid windows → "not enough data".
- Optional hourly battery samples (WorkManager, off by default) are stored as `SAMPLE` snapshots, hidden from
  History and the snapshot pickers.
- App-start time is this app's own cold start (process start → first drawn frame), kept as the last 50 samples
  in SharedPreferences. It is a proxy for system responsiveness, not a benchmark of other apps.
- Debug builds accept an intent extra `screen` (and `autoAudit`) so CI can screenshot each screen; release
  builds ignore it.
